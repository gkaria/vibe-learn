# Contributing to vibe-learn

Thanks for helping people learn from what their AI assistant builds. This guide covers the dev loop, the repo layout, and the checklist a change needs before it merges. `CLAUDE.md` is the deeper reference for how everything fits together.

## Dev setup

```bash
git clone https://github.com/gkaria/vibe-learn && cd vibe-learn
# Requirements: bash, jq, bats
brew install jq bats-core        # macOS
sudo apt-get install jq bats     # Debian/Ubuntu

bats tests/                      # full suite, ~15s
bats tests/observe.bats          # one file
```

Try your changes against a scratch project without touching your real global install:

```bash
bash scripts/install.sh /tmp/scratch-project --assistant=claude-code
# or drive a script directly with a hook payload:
echo '{"cwd":"/tmp/scratch-project","tool_name":"Write","tool_input":{"file_path":"src/index.ts"},"tool_response":{}}' | bash scripts/observe.sh
```

To test the Claude Code plugin packaging from a local checkout, inside Claude Code run `/plugin marketplace add /path/to/vibe-learn` then `/plugin install vibe-learn@vibe-learn`, or `claude plugin validate .` from the shell.

## Layout

```text
scripts/                 assistant-agnostic core (hooks, CLI, briefing, recap, knowledge ledger)
adapters/<assistant>/    per-assistant install + command/prompt/skill files
.claude-plugin/          Claude Code plugin + marketplace manifests (the repo root is the plugin root)
bin/                     wrappers on the Bash tool PATH while the plugin is enabled
.claude/commands/        dogfood copies of adapters/claude-code/commands (tests diff them)
tests/                   bats suite; one file per script or feature
docs/demo/               VHS tapes and scripted replays for the README GIFs
specs/                   design notes for larger features
```

Hooks are the hot path. `observe.sh` runs on every tool call and must stay under 50 ms: no network, no heavy jq pipelines, append-only writes. Everything expensive (briefing, recap, ledger writes) is on-demand.

## Adding a learning command

Commands are markdown instruction files the assistant follows; there is no code to run except the knowledge helper.

1. Write `adapters/claude-code/commands/<name>.md` (frontmatter `description:` plus the instructions). Ground every claim in `.vibe-learn/session-log.jsonl`; if it touches the ledger, tell the model to call `knowledge.sh` and to never hand-edit the JSON.
2. `cp` it to `.claude/commands/<name>.md` — the dogfood copy must stay identical.
3. Port it to `adapters/codex/prompts/`, `adapters/opencode/commands/`, `adapters/grok/commands/`, and `adapters/cursor/skills/<name>/SKILL.md` with each host's helper lookup and tool names (copy the preamble from the neighbouring `quiz.md` / `quiz/SKILL.md`). Add a mode section to `adapters/codex/skills/vibe-learn/SKILL.md`, `adapters/grok/skills/vibe-learn/SKILL.md`, and `adapters/cursor/skills/vibe-learn/SKILL.md`.
4. Wire it in: each adapter's `install.sh` copy lines, `scripts/setup.sh` `FILES`, `techpack.yaml`, and the printed command lists in `setup.sh` / `install.sh`.
5. Tests: `tests/<name>.bats` covering file content, install copies, and setup.
6. Docs: README command lists, `CLAUDE.md` Learning Interfaces, `GETTING_STARTED.md`, `templates/instructions.md`.

`/explain` (`tests/explain.bats`) is a complete recent example.

## Adding an assistant adapter

Create `adapters/<name>/install.sh` that registers hooks in that host's config format and copies the command files. Prefer translating the host's payload inside the adapter (see `adapters/opencode/plugins/vibe-learn.js`) so the core scripts stay generic. Add `--assistant=<name>` handling and detection to `scripts/setup.sh` and `scripts/install.sh`, a `tests/install-<name>.bats`, and a row in the README's Supported assistants table.

## Pull request checklist

- `bats tests/` passes and new behaviour has tests.
- Hook scripts stay silent on stdout and fast; nothing new runs from a hook that could run on demand instead.
- `.claude/commands/*` still match `adapters/claude-code/commands/*`.
- Docs touched: README, `CLAUDE.md`, `GETTING_STARTED.md`, `templates/instructions.md` where relevant. `CHANGELOG.md` is generated by release-please from commit messages.
- Commits follow Conventional Commits (`feat:`, `fix:`, `docs:`, `test:`, `chore:`), since they drive the changelog and version bump.

## Reporting bugs

Use the bug report template. The most useful details are your assistant and version, your `vibe-learn` version (`cat ~/.vibe-learn/VERSION` or `.claude-plugin/plugin.json`), and `.vibe-learn/session-meta.json` from the affected project. Session logs may contain your prompts, so scrub them before attaching.

## Code of conduct

Be kind and assume good faith. Maintainers may close or edit issues and PRs that are hostile or off-topic.
